# Strict CSP via per-request nonce middleware

LCKED serves a password vault whose worst-case bug is script injection: any
XSS while the vault is unlocked can invoke the in-memory key. We therefore
ship a Content-Security-Policy whose `script-src` carries real control —
per-request nonces generated by middleware on document responses, with
`'strict-dynamic'`, so inline bootstrap scripts from the framework keep
working while third-party and injected scripts cannot load. Static headers
(HSTS, framing, MIME, referrer, permissions, cross-origin isolation) ship
alongside via the framework's response-header config.

## Considered options

- **`script-src 'unsafe-inline'`** as a pragmatic first step — rejected: for
  a credential vault it licenses exactly the attack class CSP exists to stop;
  everything else the headers buy would have been theater by comparison.
- **Hash-based script allowlisting** — rejected: build chunk hashes churn
  every deploy and the list silently rots; nonces track the served page by
  construction.

## Consequences

- Development relaxes `script-src` (`unsafe-eval` for hot reload) and drops
  `upgrade-insecure-requests` (dev serves plain HTTP), both `NODE_ENV`-gated;
  production stays strict. Dev is intentionally a weaker environment than
  what users receive.

- Any future third-party script or origin (analytics, fonts, new icon host)
  requires a deliberate CSP edit and review — that friction is the point.
  Implementation lives in `src/proxy.ts` (per-request nonce + CSP
  construction — the single place to edit when adding an origin) and the
  static header set in `next.config.ts`; `scripts/security-headers-smoke.sh`
  asserts the served headers (run against `next start`, since dev never
  exercises the strict policy).

- `'wasm-unsafe-eval'` was added to `script-src` when the vault adopted
  Argon2id (ADR-0005): compiling WebAssembly requires it in every
  Chromium/Firefox/WebKit release. It permits `WebAssembly.instantiate` of
  our own bundled module only — no script evaluation — so the nonce model
  keeps full control over JS.
