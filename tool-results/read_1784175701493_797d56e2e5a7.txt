   142→## 2. Typography
   143→
   144→- **Font family:** `Inter` (web font, loaded via Proton styles), with system fallback stack. Override `--optional-font-family` allows user-switchable: System / Arial / Times / Dyslexic / Atkinson. Source: `ThemeFontFaceSetting` in `packages/colors/themes/constants.ts`.
   145→- **Default base font-size:** 16 px (`CSS_BASE_UNIT_SIZE = 4`, with 1 em = 16 px).
   146→- **Monospace:** applied via `.text-monospace` utility class for passwords, OTP codes, generated-password display. The pre tag override confirms Inter is the default; monospace falls back to browser default mono for password fields.

   212→## 4. Item List + Detail Anatomy
   213→
   214→### 4.1 List item (`ItemsListItem.tsx` + `ItemsListItem.scss`)
   215→
   216→```
   217→┌──────────────────────────────────────────────────────────────┐
   218→│ [icon] Item name                                  [shared]   │   ← px-3 py-2 (or px-2 py-1.5 in bulk)
   219→│        subtitle (color-weak, text-sm, ellipsis)              │
   220→└──────────────────────────────────────────────────────────────┘
   221→```
   222→
   223→- **Row container:** `ButtonLike` (renders as `<a>`), `shape="ghost"`, `color="weak"` (or `color="warning"` if item failed to sync), `w-full`, `border-radius: 0` (flush rows).
   224→- **Icon:** `SafeItemIcon size={5}` (outer box = `5 × 4 × 1.8` = **36 px**), `mr-3 shrink-0`, sub-theme class applied per item type (so icon color = sub-theme `--interaction-norm`). Login items try to load domain favicon; if it fails the type icon (e.g. `user`) shows. Credit-card items render the brand SVG (amex / mastercard / visa) instead of the generic icon.
   225→- **Indicators (overlaid on icon, absolute positioned):**
   226→  - Default mode: `ItemIconIndicators` — `CircleLoader` while optimistic/loading; `IcExclamationCircleFilled` (signal-warning) on failure.
   227→  - Bulk mode: `checkmark` icon pill (`background: var(--interaction-norm); color: var(--text-invert); opacity: 0 → 1` on select).
   228→  - Pinned items: `IcPinAngledFilled` in an `IconBox size=2.5` at `bottom: -6px; right: -6px`, background `var(--interaction-norm-major-1)`, color `var(--interaction-weak)`.
   229→- **Heading:** `text-ellipsis` span; matches search via `<Marks>` (highlight matched chunks). For vault-share items, a small `VaultIcon size=3` precedes the heading.
   230→- **Subtitle:** `color-weak text-sm text-ellipsis block`. Italicized when note is empty. For shared items, an `IcUsersFilled size=3.5` may follow.
   231→- **Subtitles per item type** (`presentListItem`):
   232→  - login → email-or-username (via `intoUserIdentifier`)
   233→  - alias → alias email address
   234→  - note → first line of note body (or “Empty note” in italic)
   235→  - creditCard → masked card number (`•••• 1234` style)
   236→  - identity / sshKey / wifi / custom → empty subtitle
   237→- **Active state:** `.is-active` → `background-color: var(--interaction-weak)` (the sub-theme’s tinted weak color).
   238→- **Bulk-selected state:** `background: var(--interaction-norm-minor-1) !important` plus checkmark opacity 1.
   239→- **Loading state:** `style="--anime-opacity: 0.5"` (fades whole row); icons get `opacity-50`.
   240→- **Search match color:** `<mark class="is-light">` → `color: var(--interaction-norm)` in heading; `color: var(--interaction-weak-contrast)` in subtitle; weight `--font-weight-normal`.
   241→
   242→### 4.2 Detail panel (`ItemViewPanel.tsx`, `Login.content.tsx`, `ValueControl.tsx`, `FieldsetCluster.scss`)
   243→

   245→┌─ Panel (className = sub-theme class e.g. "ui-violet") ──────────────┐

   247→│    [icon] h2 "Item name"  (text-2xl, text-bold, mb-0-5, ellipsis)   │

   249→│  ─────────────────────────────────────────────────────────────────  │
   250→│  VaultTag (which vault this item lives in)                          │
   251→│                                                                      │
   252→│  Card (bg = --interaction-weak, border-weak, rounded)               │
   253→│    h3 = capitalized item heading                                     │
   254→│    FieldsetCluster (mode="read")                                     │
   255→│      ┌─ ValueControl ─────────────────────────────────────────┐    │
   256→│      │ [icon] Label                            [actions]       │    │
   257→│      │        value (text-monospace for passwords)             │    │
   258→│      └──────────────────────────────────────────────────────────┘   │
   259→│      ┌─ ValueControl ─────────────────────────────────────────┐    │
   260→│      │ ... (next field, shares border with previous)            │    │
   261→│      └──────────────────────────────────────────────────────────┘   │
   262→│                                                                      │
   263→│  ItemHistoryStats (created / modified / last-used timestamps)       │
   264→│  MoreInfoDropdown (revision number, vault id, share id)             │
   265→└──────────────────────────────────────────────────────────────────┘
   266→```
   267→
   268→**FieldsetCluster visual rules:**
   269→- Each child has `1px solid var(--border-weak)` and `margin-block-start: -1px` so adjacent rows collapse to a single 1-px divider.
   270→- First child: top corners `--border-radius-lg`; bottom corners 0.
   271→- Last child: bottom corners `--border-radius-lg`; top corners 0.
   272→- Only child: all corners `--border-radius-lg`.
   273→- Cluster icon color: `var(--interaction-norm)` (sub-theme-aware).
   274→
   275→**ValueControl rows** (for login, in order):
   276→1. **Passkey** section (if any) — `ValueControl` with `className="pass-value-control--standout"` (subtle linear-gradient bg using `--interaction-norm-major-2`), icon `pass-passkey`, label `"Passkey • {domain}"`, chevron-right action.

   453→## 8. Drag-and-Drop Pattern (move items between vaults)
   454→
   455→### 8.1 Capability gating
   456→- **Web/Desktop only.** `useCanDragItems = !EXTENSION_BUILD`. Extension uses `VaultSelect` modal instead.
   457→- Items can be dragged only if `!loading && !failed` (per `ItemsListItem`).
   458→- Drop targets (vaults) accept drops only if `isWritableVault(vault)` (read-only / shared-as-viewer vaults reject drops).
   459→
   460→### 8.2 Drag source (`useItemDrag`, `ItemsListItem.tsx`)
   461→- The whole row is `draggable={canDrag}` on the `<ButtonLike>`.
   462→- `onDragStart` calls `handleDragStart(evt, { ID: id })` from `useItemsDraggable`.
   463→- If bulk-select is enabled and there is a selection, **all selected items** are dragged together (the hook derives the list from `bulk.selection`).
   464→- The drag image (HTML5 `DataTransfer.setDragImage`) shows a custom label: `Move {count} item` / `Move {count} items` (via `getDragHtml`).
   465→
   466→### 8.3 Drop target (`useItemDrop`, `VaultMenuItem.tsx`)
   467→- Each vault row spreads `{...dragProps}` from `useItemDrop(onDrop, dragFilter)`.
   468→- `dragFilter` returns `Boolean(vault && isWritableVault(vault))` — non-writable vaults are not droppable.
   469→- `onDrop` parses item keys (`fromItemKey`) and calls `moveMany(intoBulkSelection(items), shareId)`.
   470→- `dragOver` boolean state drives visual feedback.
   471→
   472→### 8.4 Visual feedback
   473→- While dragging over a valid vault: `VaultMenuItem` applies `.is-selected` class (same as the selected state) → `background-color: var(--interaction-norm-minor-2)`.
   474→- The drag image is the “Move N items” text label (Proton core `useItemsDraggable`).
   475→- No separate drop-zone outline animation is applied (relies on the existing selected-state background).
   476→
   477→### 8.5 Alternative: bulk-move modal
   478→When bulk-select is active, the `BulkActions` toolbar shows a `Move` button (`IcFolderArrowIn`) that opens the `VaultSelect` modal instead of dragging. Same `moveMany` action under the hood.
   479→
   480→### 8.6 Per Proton support doc (`proton.me/support/pass-bulk-select-items`)
   481→> “To move items to another vault, you can either drag and drop them directly or select Move. To delete items, select Trash.”
   482→
   483→Confirmed: DnD is a first-class move mechanism, not a secondary affordance.
   484→
   485→### 8.7 Item-reorder DnD
   486→**Not implemented** — Proton Pass does not support manual reordering within a vault (sort is governed by `SortFilter`: relevant / recent / alphabetical / newest / oldest). This is a deliberate design choice.
   487→
   488→### 8.8 Reorder vaults
   489→**Not implemented** — UserVoice request exists (`protonmail.uservoice.com/.../drag-and-drop-between-vaults`); Proton has not shipped vault reordering. Vaults are listed in creation/share order.
